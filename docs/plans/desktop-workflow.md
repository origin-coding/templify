## 1. 目标和范围

将现有桌面单页上的三个卡片改造成三个步骤视图：选择模板、准备数据、设置输出。顶部使用 TDesign Steps，底部提供上一步、下一步或生成按钮。生成过程和结果在输出步骤展示，不增加第四个操作步骤。

完成手动多记录输入、Excel/CSV 导入和预览、Excel 填写模板导出，以及单 DOCX、目录和 ZIP 输出的桌面入口。复用现有核心与文件适配器，不复制 CLI 业务逻辑。

本轮不实施 PDF 预览和打印；它们是生成完成后的后续操作。核心已有 PDF 转换和合并能力，不应重新设计转换引擎，也不要删除已有能力。此次桌面主流程使用 DOCX 输出，不新增 PDF 输出选择或合并文档模式。

不引入持久化、草稿恢复、数据库、账户、模板管理平台、导入表格就地编辑、嵌套集合或新的集合标签语法。关闭应用后不恢复任务。

## 3. 已确定的产品行为

### 3.1 步骤导航

- 支持上一步和点击已到达步骤；未到达步骤不能点击跳过。
- 已到达不等于当前依赖有效。进入数据页必须有有效模板；进入输出页必须有当前有效记录。
- 返回前一步保留本次输入，组件卸载不丢失任务数据。
- 区分当前步骤、到达历史、依赖有效性和执行状态，避免仅凭最大步骤下标判定所有步骤完成。
- 编辑数据或输出配置后，旧输出计划、检查结果和生成结果失效。恢复有效数据后可重新进入输出步骤。
- 执行生成时锁定会改变任务的操作，避免数据或模板在执行中被替换。

### 3.2 模板替换和任务重置

- 成功选择新模板后重新解析，清空旧输入、导入来源、诊断、输出配置、预览和生成结果，重置步骤到达状态。
- 不按同名字段迁移数据，不合并新旧字段，不做增量更新。
- 取消文件选择保留任务。选择了新模板但解析失败时，不允许继续使用旧模板生成；清理旧任务并展示模板错误。
- 开始新任务统一清理 renderer 与 main 的任务状态、运行期句柄及临时监听。

### 3.3 输入方式

- 提供手动输入和 Excel/CSV 输入两种互斥模式。
- 实际切换模式时清空已有记录、当前记录选择、输入诊断、输出预览及结果。再次选择当前模式不重置。
- 不混合输入来源，不追加导入记录，不提供新旧数据合并。
- 文件导入成功后整体替换。取消文件选择保留状态；确认新文件后若导入失败，则清除旧的有效批次，展示本次错误，阻止下一步。
- Excel 主工作表默认使用现有解析规则，提供可见工作表选择入口；切换主表重新解析当前文件，不叠加数据。
- CSV 使用现有 UTF-8/GBK 支持；必要时提供编码选择以便重新读取。不要实现复杂自动推断。

### 3.4 手动输入

- 左侧记录列表，右侧当前记录表单；支持根记录添加、删除和修改。
- 字段编辑即时写入本次任务状态，不增加保存记录按钮。
- 每条记录有稳定的 UI 标识；删除或切换记录时正确维护选择。UI 标识不进入核心记录数据。
- 普通字段按已有 hint 使用 TDesign 文本、数字、布尔、日期、日期时间和选项控件。
- 集合继续使用现有一层集合模型，嵌在当前记录表单中，支持集合项增删和字段编辑；不引入嵌套编辑器。
- 新建手动任务默认创建一条空记录，沿用现有字段默认值。零条有效记录不能进入输出步骤。
- 数字、日期等控件的值格式在 IPC 边界明确处理；不能让空数值被误转成 0，也不能让时间转换隐式改变既有语义。

### 3.5 文件输入和集合预览

- 数据页文件模式提供保存 Excel 填写模板、选择文件导入、重新导入、导入摘要、预览和错误列表。
- Excel 模板导出只需要当前有效模板，不要求已有记录；通过系统保存对话框保存 XLSX。
- 主表一行对应一条根记录，也对应一份待生成 DOCX。集合项不计入文档数量。
- 集合单元格显示可点击的共 N 项；点击后在当前行下面原地展开集合明细表，不使用弹窗。
- 同一记录有多个集合时，展开区域以 Tabs 切换；默认选中刚点击的集合。
- 默认只展开一条根记录，展开另一条时收起前一条。集合明细较多时内部分页。
- 空集合显示共 0 项，不提供展开。
- 根表和集合明细均为只读；查看 Tabs、展开和分页状态留在局部组件。
- 预览以关联后的记录为主要视图。诊断位置必须保留原始工作表、行、列，不能用预览分页行号代替源位置。
- CSV 遇到集合模板时，明确提示改用 Excel 或手动输入，沿用现有限制。

### 3.6 输出和完成操作

- 输出模式为单 DOCX、目录、ZIP。单 DOCX 接受恰好一条记录；多条记录时禁用该选项并说明原因。
- 目录和 ZIP 支持现有路径模板，遵守核心现有语法和安全规则，不增加表达式功能。
- 用户在生成前选择输出位置。单文件/ZIP 使用保存对话框，目录使用目录选择对话框。
- 默认冲突策略为 error，只有明确选择覆盖时使用 overwrite。
- 输出页展示模板摘要、根记录数、DOCX 数量、输出模式、位置和规划后的安全文件路径。
- ZIP 同时展示归档文件位置和内部 DOCX 条目路径，不能把条目误显示为磁盘文件。
- 生成前预览不渲染 DOCX、不转换 PDF、不写输出文件；预览必须来自同一核心生成/发布计划，不能在 Vue 中自行拼接一套路径算法。
- 修改模板、数据、输出设置后清除旧计划；生成时执行真实预检，处理预览后文件系统变化和冲突。
- 成功后提供打开输出位置、返回修改、开始新任务。单文件和 ZIP 可在文件管理器中定位文件，目录模式打开目录。
- 返回修改保留模板、记录及输出配置；再次实际编辑时使旧结果和计划失效。开始新任务清空本次状态。

## 4. 状态和进程边界

### 4.1 Pinia

引入 `pinia` 与适配 Nuxt 4 的 `@pinia/nuxt`，接入现有 Nuxt 配置。正确适配项目的自定义 `srcDir`；不要额外创建第二个 Vue/Pinia 根实例。

先只建立一个 `useGenerationStore`，管理本次生成任务，不按步骤拆成相互依赖的多个 Store，也不引入持久化插件或 localStorage。

Store 包含：模板展示信息、输入方式、手动记录草稿、当前记录选择、导入批次展示数据与来源、输入诊断、输出配置与计划摘要、当前步骤和到达状态、执行阶段、结果与任务版本标识。

记录数量、是否允许单文件输出、是否能进入下一步等尽量使用 getters/computed。将模板替换、模式切换、导入替换、输出失效和任务重置集中在明确的 actions 中，避免页面各自修改几个标志而遗漏其他状态。

表格展开、分页、集合 Tabs、控件焦点等局部状态留在组件中。控制项不得意外持久化到业务记录。

### 4.2 Electron 与核心

- renderer 负责展示与编辑草稿，Store 组织调用；main 负责对话框、文件、核心服务及输出。
- 不向 renderer 传递 PreparedTemplate、Generation、文件句柄或 DOCX 字节；可使用简单运行期任务/批次标识管理 main 内状态。
- 文件导入保留 RawInputBatch 和来源信息，并生成只读预览；计划阶段复用原始批次或其可靠句柄，不把预览字符串再当输入解析。
- 手动记录经受控 IPC 快照提交，去除 Vue 代理和 UI 标识；main 使用核心规范化，不信任 renderer 的有效标志或生成数量。
- 扩展 shared 契约、preload 白名单与 main 注册，保持结构化结果，明确区分取消、失败、成功和 warnings。
- 所有 IPC 检查发送者、参数形状和当前任务；保留 contextIsolation、关闭 nodeIntegration 和现有导航限制。
- 任务替换或输入修改后，异步返回不得覆盖新状态；用任务版本或句柄检查陈旧结果。
- 打开输出位置仅接受当前任务返回的已知输出标识，由 main 解析实际路径；不提供任意 shell 命令执行接口。

建议按职责提供模板选择、导入/重读、Excel 模板保存、输入检查、输出位置选择、输出计划预览、生成执行、结果位置打开和任务重置等接口。具体命名由执行者结合现有风格确定，不要求一个操作对应一个新模块。

## 5. 诊断、进度和失败语义

当前 DesktopIssue 仅有 stage/code/details，页面把 details 当字符串展示。扩展为保留原始结构化位置、错误和 warnings 的契约，并提供易懂的中文摘要；保留 code 和技术详情供排查。

输入错误显示工作表、源行/列、字段或集合项位置；用户修改源文件后重新导入。手动输入错误定位到根记录和对应控件。库仅返回一个错误时如实展示，不承诺一次收集全部错误。

Steps 表示操作步骤，生成进度表示执行阶段。第一轮可以提供真实阶段提示和 loading，不能用计时器制造百分比。只有核心实际发出逐份回调时才展示已渲染 N/M；如确有必要，最小化增加可选进度回调，不能为进度重复渲染或改成逐份单独发布。

现有行为是先生成内存产物，再打包和发布；渲染/打包失败不发布部分文件。发布失败会尝试回滚，因此失败页面不能把已渲染数量显示为已保存数量。

- 渲染、打包失败：展示失败阶段、记录位置，以及本次没有完成发布。
- 发布失败：展示失败路径和回滚结果；保留 TemporaryFileCleanupFailed、BackupCleanupFailed、RollbackFailed 等警告及路径。
- 已确认成功发布时才展示已保存数量。回滚失败且无法确定最终数量时，明确显示状态未完全恢复和需要检查的位置，不能猜测残留数量。
- 不为失败提示引入新的部分成功发布策略，不削弱现有预检、文件保护和回滚。

## 6. 建议实施顺序

### 阶段 A：状态和步骤壳

接入 Pinia，提取任务 Store，拆出步骤组件；保留现有模板检查和手动单文档生成的可用路径。完成步骤导航、重置和状态失效规则。

### 阶段 B：手动多记录

实现记录列表加单条表单，提取可复用的简单字段控件，迁移现有集合编辑。完成记录选择、增删、即时更新和输入检查。不要复制两套普通/集合字段控件逻辑。

### 阶段 C：表格文件

为 desktop 添加 `@templify/tabular-input` 工作区依赖，通过 main 接入 Excel 填写模板保存和 Excel/CSV 导入。实现主工作表/CSV 编码选择、整体替换、摘要、只读主表、集合原地展开和诊断。

### 阶段 D：输出规划和执行

把现有单文档 IPC 扩展或替换为批次规划和执行流程，接入目录/ZIP、保存位置、路径模板、冲突策略和计划预览。使用现有 prepareGeneration → publication plan/preflight → generateArtifacts → packageArtifacts → publishArtifacts 顺序。

预检必须在昂贵生成前执行，并在真正发布阶段沿用现有文件变化检查。保护 DOCX 模板和导入源文件，不能覆盖本次输入源。

### 阶段 E：结果和布局验证

接入三个完成操作，完善真实阶段提示、结构化错误和回滚警告；核对空状态、长路径、多字段、多集合和小窗口布局。完成针对改动的验证及仓库检查。

步骤组件、表单、导入预览、集合预览和输出配置可以放在 `apps/desktop/src/renderer/components` 下，Store 放在 renderer 的 stores 下。文件名保持英文；按实际职责拆分，不引入通用表单平台、状态机框架或大服务容器。

## 7. 验收条件

### 操作与状态

- [ ] 三个步骤视图和顶部 Steps 工作正常，支持上一步和已到达步骤；前置条件无效时不能绕过。
- [ ] 返回页面保留输入；更换模板、切换输入方式、重新导入和开始新任务符合本文约定。
- [ ] 取消对话框不清空任务；选择新模板失败或确认新文件导入失败时不误用旧数据。
- [ ] 快速重复操作或陈旧 IPC 响应不会把旧模板/输入写回新任务。
- [ ] 关闭后不恢复状态，无持久化依赖。

### 输入

- [ ] 根记录可增删修改，无保存记录按钮；删除当前记录后选择正确。
- [ ] string、number、boolean、date、datetime、option 与现有核心转换兼容。
- [ ] 一层集合可编辑，集合项不会增加根记录数或文档数。
- [ ] Excel 模板保存复用既有协议和格式，无集合时不添加关联列。
- [ ] Excel/CSV 按字段名称匹配；重排列、额外列、空行和原始字符串编号遵循已有行为。
- [ ] Excel 多集合按既有 ID 正确关联；主表切换、空集合、重复 ID、未知父 ID 和缺失表诊断可理解。
- [ ] CSV 的集合限制和编码选择明确，导入预览不能编辑。
- [ ] 集合共 N 项可原地展开，多集合 Tabs、单条展开、空集合和明细分页行为正确。
- [ ] 错误位置使用真实源表/行/列，手动错误能定位到记录与字段。

### 输出

- [ ] 一条记录可生成 caller-named DOCX；多条记录不能选择单文件，目录和 ZIP 按接受的计划顺序生成独立 DOCX。
- [ ] 输出位置在生成前选定，实际安全路径来自核心计划，预览本身不写文件。
- [ ] ZIP 文件位置和条目路径展示正确，生成数量只计根记录。
- [ ] 默认 error，只有明确选择 overwrite 才覆盖；保留输入保护、路径安全和预览后变化检查。
- [ ] 修改数据/配置后旧预览不可执行；预检失败不会开始渲染。
- [ ] 失败报告区分已渲染和已发布，回滚/清理警告不丢失。
- [ ] 成功后可打开输出位置、返回修改和开始新任务。
- [ ] 本轮没有加入 PDF 预览、打印或多记录合并 DOCX。

## 8. 验证与交付

沿用现有 Vitest 和真实 DOCX/CSV/XLSX 测试约定。对新增任务状态失效、IPC 结果映射和桌面批次服务编写有意义的测试；已有库功能已有测试时不重复创建只镜像实现的测试。
